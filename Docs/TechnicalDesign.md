## 구조

```
Plugins/VW/                 날씨 렌더링 플러그인
  Source/VW/                런타임 모듈 (렌더 그래프 패스, 날씨 액터, 파라미터)
  Source/VWEditor/          에디터 모드
  Shaders/Private/          HLSL 셰이더
Source/EyeOfTheStorm/       게임 모듈
  Character/                플레이어, 보스, 공통 베이스
  Combat/                   체력, 근접 공격, 락온
  AI/                       보스 AI 컨트롤러와 비헤이비어 트리 노드
  Animation/                판정 구간, 콤보 입력 구간, 공격 전진, 예고 장판 노티파이
  Weather/                  날씨 서브시스템, 프리셋, 체력 날씨, 낙뢰
  UI/                       HUD, 체력바
Tools/                      에디터 자동화 스크립트 (UE Python)
```

게임 로직은 C++로 쓰고, 블루프린트는 수치와 에셋 지정, 위젯 배치 같은 데이터와 연출만 맡습니다.

## 날씨 렌더링 플러그인

자체 제작한 Vulkan 렌더러 [VolumetricWeather](https://github.com/Shell4026/VolumetricWeather)를 UE5로 이식했습니다. 엔진의 SkyAtmosphere와 VolumetricCloud를 쓰지 않고, `SceneViewExtension`으로 렌더 그래프(RDG)에 패스를 직접 넣습니다.

### 패스

| 패스 | 내용 |
| --- | --- |
| Transmittance LUT, Multiple Scattering LUT | 대기 산란 사전 계산. 날씨 값이 바뀔 때만 다시 굽습니다 |
| Sky View LUT, Aerial Perspective LUT | 하늘색과 거리별 대기 원근 |
| 태양 깊이, Aerial Shadow | 태양 쪽에서 찍은 깊이로 대기 속 체적 그림자(빛줄기)를 만듭니다 |
| Cloud, Cloud Temporal Reprojection | 레이마칭 구름. 프레임마다 1/16 픽셀만 새로 계산하고 이전 프레임을 재투영해 채웁니다 |
| Composite | 씬 컬러 위에 하늘, 구름, 대기 원근을 합성합니다 |

### 좌표계는 경계에서 한 번만 변환

원본 셰이더는 Y-up, km 단위이고 UE는 Z-up, cm 단위입니다. 셰이더를 UE식으로 다시 쓰는 안도 검토했지만 다음 이유로 경계에서 변환하기로 했습니다.

- cm 단위로 행성 반지름(약 6,360km)을 다루면 float 정밀도가 약 64cm까지 떨어집니다.
- UE의 SkyAtmosphere도 `CM_TO_SKY_UNIT`으로 cm를 km로 바꿔 셰이더에 넘깁니다.
- 대기와 구름 셰이더 전체가 Y-up을 가정하고 있어서, 셰이더를 고치면 원본과 나란히 비교하며 검증할 수 없게 됩니다.

그래서 C++에서 셰이더로 값을 넘기는 지점(카메라, 태양 방향, 위치)에서만 변환하고 셰이더는 원본 좌표계를 그대로 씁니다.

### 커브를 상수 버퍼로 넘기기

구름 밝기는 에디터 커브로 편집합니다. 게임 스레드에서 커브를 32점 샘플해 상수 버퍼의 `float4[8]`로 보냅니다. 상수 버퍼 배열은 원소마다 16바이트로 정렬되므로 `float[32]`로 보내면 4배 공간을 쓰게 되어 4개씩 묶었습니다. 텍스처가 아니라서 RDG 리소스를 따로 만들 필요가 없습니다.

### 태양 깊이 캡처 범위

빛줄기는 태양 쪽에서 직교 투영으로 찍은 깊이를 씁니다. UE의 직교 SceneCapture는 원평면이 약 2.6km로 고정되어 있어(`BuildOrthoMatrix`), 원본의 10km 캡처 거리를 그대로 옮기면 깊이가 전부 원평면 값으로 찍혔습니다. 커스텀 직교 행렬을 넘겨 캡처 거리 10km, 원평면 20km로 맞췄습니다.

### 투과율 조기 종료

구름 레이마칭은 투과율이 0.01 아래로 떨어지면 멈춥니다. 그래서 두꺼운 폭풍 구름은 몇 스텝 만에 끝나고, 맑은 하늘의 옅은 구름이 오히려 끝까지 걷습니다. 날씨별 비용이 직관과 반대로 나오는 이유입니다 ([성능](#성능)).

### 재투영 히스토리 가중치

보스가 하늘 앞에서 움직이면 윤곽을 따라 하늘색 잔상이 남았습니다. 재투영 누적이 "구름 없음"인 무효 히스토리를 유효한 샘플 하나로 세고 있었기 때문입니다. 원본 렌더러에서 물려받은 결함으로, 원본 장면에는 하늘 앞을 움직이는 물체가 없어서 드러나지 않았습니다. 무효 히스토리를 누적에서 빼도록 고쳤습니다.

## 성능

RTX 3060 Ti, 1920x1080, 독립 실행 기준 GPU 시간 (ms)

| | 맑음 | 폭풍 |
| --- | --- | --- |
| VW 전체 | 1.03 | 0.78 |
| VW.SkyViewLUT | 0.09 | 0.09 |
| VW.AerialPerspectiveLUT | 0.02 | 0.03 |
| VW.Cloud | 0.70 | 0.49 |
| VW.Composite | 0.20 | 0.16 |
| 프레임 전체 | 7.17 | 6.94 |

- 구름이 두꺼운 폭풍이 맑음보다 VW 전체 기준 0.25ms 적게 소요됩니다. 투과율 조기 종료 때문입니다.
- 하늘은 고정 크기 LUT라서 해상도를 올리면 구름 패스만 늘어납니다.
- 날씨가 섞이는 동안에는 대기 LUT를 매 프레임 다시 굽습니다. 날씨 서브시스템은 적용한 구간과 비율이 지난번과 같으면 값을 다시 넘기지 않아, 날씨가 멈춰 있을 때는 LUT를 굽지 않습니다.

## 게임플레이

### 날씨 서브시스템

`UStormWeatherSubsystem`(월드 서브시스템)이 레벨의 날씨 액터와 높이 안개를 함께 바꿉니다. 날씨는 프리셋 에셋(`UStormWeatherPreset`) 단위로 다룹니다.

- **트랙**: 기준점(위치와 프리셋) 목록을 받아, 현재 위치가 두 기준점 사이면 두 프리셋을 그 비율로 섞습니다. 위치는 목표를 향해 일정 속도로 따라가서, 한 번에 큰 피해를 받아도 하늘이 툭 바뀌지 않습니다.
- **전환**: 지금 상태에서 프리셋 하나로 정해진 시간 동안 넘어갑니다. 전환 중에 다시 부르면 그 순간의 날씨에서 이어서 바꿉니다.
- **장소 값 유지**: 위도, 자전축, 시간 흐름 속도, 대기 두께처럼 장소에 딸린 값은 프리셋으로 덮지 않고 레벨에 둔 값을 그대로 씁니다.

### 체력 날씨 컴포넌트

체력에 따라 날씨를 바꾸는 로직은 보스 클래스가 아니라 `UStormHealthWeatherComponent`에 있습니다. 체력 컴포넌트가 있는 액터라면 어디든 붙일 수 있고, 날씨가 필요 없는 보스에는 붙이지 않으면 됩니다.

- 기준점마다 날씨가 완성되는 체력 비율을 정하고, 정하지 않으면 체력 컴포넌트의 페이즈 경계(66%, 33%)를 씁니다.
- 체력이 바뀌면 서브시스템 트랙의 목표 위치만 옮깁니다.
- 소유 액터가 죽으면 잠시 뒤 첫 기준점(맑음)으로 되돌립니다.

### 번개와 낙뢰

`UStormLightningComponent`가 마지막 페이즈에 들어가면 낙뢰를 시작합니다.

- 플레이어 발밑에 하나, 아레나 무작위 지점에 몇 개의 예고 장판을 깔고, 1.2초 뒤 낙뢰가 떨어집니다. 무작위 지점끼리는 최소 간격을 둡니다.
- 무작위 지점은 아레나 높이 근처에서만 바닥을 찾아, 낭떠러지 아래 땅에 떨어지지 않게 합니다.
- 낙뢰와 별개로 하늘 플래시가 무작위 간격으로 아레나를 밝힙니다.

### 보스 AI

보스는 비헤이비어 트리로 움직입니다. 서비스 노드가 대상과 지금 쓸 수 있는 패턴이 있는지를 블랙보드에 갱신하고, 공격 태스크가 패턴(몽타주)을 실행합니다. 공격 판정과 예고 장판은 애니메이션 노티파이 구간으로 몽타주에 붙입니다.

### 전투

- 락온, 무적 프레임이 있는 회피. 락온 중 뒤쪽으로 입력하면 대상을 본 채 뒤로 구릅니다. 회피 중 누른 회피 키는 기억해 두었다가 끝나자마자 이어 구릅니다.
- 3타 콤보: 콤보 입력 구간과 판정 구간을 노티파이 상태로 몽타주에 표시합니다. 판정은 지난 프레임 위치에서 이번 프레임 위치까지 구를 스윕해서, 빠른 발차기가 프레임 사이로 빠져나가지 않게 합니다.
- 히트스톱, 공격할 때 앞으로 붙는 전진
- 낭떠러지에서 떨어지면 즉사합니다.

### 보스 사망 디졸브

디졸브 재질은 Masked라서 전투 내내 쓰면 불투명 재질보다 비쌉니다. 그래서 전투 중에는 원래 재질을 쓰고, 죽는 순간에만 슬롯별로 디졸브 재질로 바꿔 끼웁니다.

- 노이즈 좌표를 스킨 전 위치(`PreSkinnedPosition`)로 잡아 쓰러지는 동안 무늬가 몸에 붙어 있습니다. 이 값은 정점 셰이더에서만 읽을 수 있어 Vertex Interpolator로 넘깁니다.
- 사망 몽타주는 자동 블렌드 아웃을 꺼서 마지막 포즈를 유지하고, 몽타주 길이에 맞춰 디졸브를 진행합니다.

## 디버깅 사례

### 연속 구르기 때 한 프레임 카메라가 튐

연속으로 구르면 한 프레임만 카메라가 돌아갔다 돌아왔습니다. 모션 블러와 TSR을 끄고 앞뒤 프레임을 캡처해 카메라 문제임을 확인했습니다. 원인은 월드 틱 순서였습니다. 틱 그룹, 타이머, 카메라 갱신 순서로 돌기 때문에, 타이머에서 시작한 버퍼 회피가 캐릭터를 180도 돌리면 스프링 암이 같이 돌아 그 프레임만 카메라가 튀었습니다. 입력에서 시작한 회피는 스프링 암 틱 전이라 문제가 없었습니다. 스프링 암이 캐릭터 회전을 물려받지 않게 고쳤습니다.

### 모프 타깃이 얼굴을 줄임

직접 만든 캐릭터의 모든 모프 타깃이 값 1에서 얼굴을 줄였습니다. 블렌더, FBX 파일, UE 임포터 순서로 나눠 확인했습니다.

1. 블렌더에서는 정상
2. FBX를 직접 파싱해 셰이프 키 137개의 차이값이 정상임을 확인
3. 기존 레거시 FBX 임포터로 가져오면 정상

원인은 UE 5.7 Interchange 임포터였습니다. 시간 0 포즈를 바인드 포즈로 쓸 때 기본 메시만 다시 스키닝하고 모프 타깃은 그대로 둡니다. 그래서 블렌더에서 머리 본에 준 1.05배 스케일이 모든 모프 타깃에 섞였습니다. 블렌더에서 포즈 스케일을 지우고 애니메이션 블루프린트에서 다시 곱했습니다.
